## Recorded transformation

Read-only evidence: `crates/board-hwr/prepare_texteller_int8.py`, its pinned requirements and `models/texteller-int8/optimization.json`. The latter's original bytes have SHA-256 `61565063571e6c75f7e44879fd358dff9a5a4f28e0f51f58e97f8405c82a13a8` (1347 bytes). `INT8-PROVENANCE.txt` is an allowlisted extraction, NOT a verbatim copy or a new conversion manifest. It contains no machine/user identities, absolute paths, benchmark data or handwriting samples.

- Format: `texteller-dynamic-int8-v1`.
- Recorded conversion tools: `onnx 1.18.0`, `onnxruntime 1.22.0`.
- Method: ONNX Runtime `quantize_dynamic`; selected operator types `MatMul` and `Gemm`, signed `QInt8` weights, `per_channel=true`, `reduce_range=true`.
- Script options additionally observed: `MatMulConstBOnly=true`, `use_external_data_format=false`. These are script evidence, not extra fields asserted to exist in the manifest.
- This is selective dynamic quantization of eligible weights, NOT quantization of every tensor/operator. Other operators can remain floating point. Dynamic activation quantization occurs where generated by the converter; no calibration dataset or accuracy evaluation is implied.
- Converter implementation verifies installer-pinned original inputs, rejects external tensor references, converts encoder/decoder sequentially in separate processes, checks I/O signatures and ONNX validity, then publishes a separate output directory. These are observed code checks, not checks rerun in this review or an execution attestation.
- The script copies `config.json`, `generation_config.json` and `tokenizer.json` without intended content changes. It does not retrain the tokenizer or license it independently.
